## 改修の全体像

旧STEP2「市場検証→書籍プロファイル確定」を、市場検証強化のため2つのSTEPに分割します。

```
旧構成:
  STEP1(草案) → STEP2(市場検証+確定) → STEP3〜9

新構成:
  STEP1(草案・改訂)
    → 新STEP2(キーワード絞り込み・新規)
    → 新STEP3(競合レビュー評価・新規)
    → 【書籍プロファイル確定アクション】受講生の明示的操作
    → STEP4〜10(旧STEP3〜9から番号繰り上げ)
```

STEP数は全16ステップ(STEP0 + STEP1〜STEP15)になります。

### 相談機能の住み分け(v4で明確化)

| STEP | 相談機能 | 備考 |
|------|---------|------|
| STEP0 | あり(既存) | 著者プロファイル |
| STEP1 | あり(既存) | 書籍プロファイル草案 |
| **STEP2** | **なし** | 客観データ分析のためAI判定アシストで代替 |
| **STEP3** | **なし** | 客観データ分析のためAI判定アシストで代替 |
| **確定アクション** | **あり(新規)** | 統合確定版の最終レビュー |
| STEP4〜10 | あり(既存) | 番号繰り上げのみ |

相談機能は`src/DiscussionPanel.jsx`として実装済み。新規実装する確定アクションにも同じ仕組みを適用する。詳細は全体設計書v4 セクション9-2参照。

### 優先度2: 新STEP2の実装(キーワード絞り込み)

  - HTTPリクエストノード × 10(並列): Real-Time Amazon Data API呼び出し

  - LLMノード: 意図合致判定 + 戻りフィードバック生成

### 優先度3: 新STEP3の実装(競合レビュー評価)

- Difyワークフロー新規作成
  - HTTPリクエストノード × 3: Top Product Reviews API呼び出し
  - LLMノード: 不満点・差別化ポイント抽出 + 戻りフィードバック生成

## 実装上の重要な制約

### コード品質

- **変数名**: `author_profile`(著者プロファイル)、`work_profile`(書籍プロファイル)を使用
- **UI文言**: 「著者プロファイル」「書籍プロファイル」で統一
- **エラー文言**: ですます調・口語調・言い切り型(「だ」を使わない)・英語/カタカナ語を避ける

### ブランド美学(維持必須)

- カラー: ネイビー × ゴールド × ホワイト
- フォント: Noto Sans Japanese
- 強調: 見出しの太字・サイズで区別(アイコンは使わない)
- ミニマル・知的・ビジネス寄り

### セキュリティ

- **APIキーは絶対にgitに含めない・スクショに映さない**
- 漏洩時は即RapidAPIコンソールでローテーション
- 受講生にAPIキーを見せない(バックエンド経由でのみ使用)

### 機能仕様

- 書籍プロファイル確定は**受講生の明示的なボタン押下**で実行(自動生成しない)
- 戻り先は常にSTEP1のみ(複雑な分岐を避ける)
- STEP2/3のAPI呼び出しは時間がかかるため、進捗表示を必ず実装(タイムアウト2分)
- 発売予定日(未発売本)はスコアリングから除外する処理を実装
- STEP4以降のDifyプロンプトは**変更しない**(書籍プロファイル確定版を参照する設計を維持)

## PoC検証済み情報

API動作確認は完了しています。以下を前提として進めて構いません。

### Product Search エンドポイント

- パス: `/search`
- パラメータ: query, country=JP, page=1
- 1リクエストで40〜50件取得可能
- 日本Amazon対応・日本語キーワードOK

### Top Product Reviews エンドポイント

- 正確なパス名は実装時にRapidAPIコンソールで確認
- パラメータ: asin, country=JP
- 1リクエストで約8件のレビュー + rating_distribution取得
- cookie不要で動作(PoC検証済み)
- 日本語レビュー本文・文字化けなし

### 注意点

- 通常の`Product Reviews`エンドポイントはcookie必須のため**利用しない**
- レスポンス構造の詳細は実装指示書v4のセクション5.4を参照
