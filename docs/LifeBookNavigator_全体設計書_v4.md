## v4での主な更新点(2026年5月15日)

### 背景

v3作成時、参照元の設計書から「相談機能(セクション9-2)」の記載が漏れていた。実際にはai-pub-producerのフロント側に`src/DiscussionPanel.jsx`として全STEPに実装済みである。v4で記載を復活させる。

### 主な変更

1. **セクション9-2「相談機能」の記載を復活**: 既存実装の仕様を完全に反映
2. **新STEP2/3には相談機能を実装しない**: 客観データ分析のため、外部AI相談の価値が低い
3. **書籍プロファイル確定アクションに相談機能を追加**: 統合された確定版を外部AIでレビューする価値が高い
4. **相談機能の役割整理**: 「主観・統合のSTEPには相談、データ分析STEPには相談なし」というルールを明確化

### 相談機能の住み分け

| STEP | 相談機能 | 理由 |
|------|---------|------|
| STEP0 | あり | 著者プロファイルの主観要素レビュー |
| STEP1 | あり | コンセプトの主観要素レビュー |
| STEP2 | **なし** | Amazon実データ分析のため外部AIで評価不可 |
| STEP3 | **なし** | Amazon実レビュー分析のため外部AIで評価不可 |
| 確定アクション | **あり(新規)** | 主観+客観の統合版を最終レビュー |
| STEP4〜10 | あり | 各成果物のレビュー |

## v3での主な更新点(2026年5月15日)

### 改修の背景

旧STEP2「市場検証→書籍プロファイル確定」は、市場検証の機能が不十分だった(検索キーワード3軸が著者目線の独自概念、レビュー数集計のみで読者ニーズが見えない、など)。これを2つのSTEPに分割し、市場データに基づく検証を強化する。

### 主な変更

1. **STEP1の改訂**: 検索キーワード3軸を削除し、コンセプト設計に専念
2. **新STEP2「キーワード絞り込み」を追加**: Real-Time Amazon Data APIで需要・競合・読者意図を3軸スコアリング
3. **新STEP3「競合レビュー評価」を追加**: 競合本のレビューを分析し、差別化ポイントを抽出
4. **書籍プロファイル確定を「明示的なユーザーアクション」に変更**: 新STEP3完了後、受講生が「確定する」ボタンを押下することで生成
5. **旧STEP3〜9を新STEP4〜10に番号繰り上げ + STEP11/12/13 新規実装**: 全STEP数 16→**14**(STEP0 + STEP1〜13)
   - 旧 STEP11(A+コンテンツ)/STEP12(プレゼント企画) は計画から削除
   - 旧 STEP13(X投稿)/STEP14(出版状況分析)/STEP15(次回作構想) を繰り上げて **STEP11/12/13** として実装（番号飛びを避けるため）
6. **STEP4以降の入力構造は変更なし**: 書籍プロファイル確定版を参照する設計を維持

### API採用

- 名称: Real-Time Amazon Data
- 提供者: FlyByAPIs
- 経由: RapidAPI(現Nokia API Hub)
- PoC検証済(2026年5月15日)
- プラン: Basic無料(月100リクエスト) → サブスク開始時にPro($14.99/月、月10,000リクエスト)へ移行

## 7. 全体フロー(循環設計)

二層プロファイル(著者プロファイル × 書籍プロファイル)による循環構造。

```
┌──────────────────────────────────────┐
│ STEP0  著者プロファイル作成・更新     │ ← 全STEPに自動注入
└────────────┬─────────────────────────┘
             ↓
┌──────────────────────────────────────┐
│ 【書籍プロファイル確立フェーズ】       │
│                                      │
│ STEP1  書籍プロファイル草案           │
│   ↓                                  │
│ STEP2  キーワード絞り込み             │
│        (Amazon API市場検証)           │
│   ↓ ← STEP1へ戻るルートあり          │
│ STEP3  競合レビュー評価               │
│        (Amazon API読者ニーズ分析)     │
│   ↓ ← STEP1へ戻るルートあり          │
│ 【受講生の確定アクション】             │
│ 「書籍プロファイルを確定する」ボタン   │
│   ↓                                  │
│ 書籍プロファイル確定版が生成・保存     │
└────────────┬─────────────────────────┘
             ↓
┌────────────────────────────────────────┐
│ 【制作フェーズ】                        │
│ STEP4〜10  制作(エピソード→説明文)     │
│ STEP11   出版後プロモーション(SNS短文)  │
└────────────┬───────────────────────────┘
             ↓
┌──────────────────────────────────┐
│ STEP12  本の改善提案(RapidAPI)    │
└────────────┬─────────────────────┘
             ↓
┌──────────────────────────────────────────┐
│ STEP13  出版経験の振り返り                │
│   ・著者プロファイル更新版（主役）         │
│   ・次回作テーマ候補（参考・著者の判断）   │
└────────┬─────────────────────┬───────────┘
         ↓                     ↓
   ┌──────────────┐     ┌─────────────────┐
   │ 新規プロジェクト │     │ 著者プロファイル │
   │ → STEP1へ      │     │ 更新 → STEP0へ │
   └──────────────┘     └─────────────────┘
   (書籍ごとに循環)        (著者の核は累積進化)
```

### 二層循環の意味

- **書籍プロファイル**は本ごとにリセット → 各本が固有のポジションを持つ
- **著者プロファイル**は累積進化 → 出版を重ねるほど核が強化される
- ユーザは「使うほど自分専用」の体験を、二層構造で実感する

### 書籍プロファイル確立フェーズの新設計

STEP1〜3は「書籍プロファイル確立フェーズ」として一体運用する。

**設計思想**: 「人が判断 → AIが整理 → 人が判断」を3段階で実装する。

```
段階1: 人が判断
  STEP1で書籍コンセプトを設計(草案)

段階2: AIが整理
  STEP2でAmazon APIから市場データ取得→スコアリング
  STEP3でレビュー分析→差別化ポイント抽出

段階3: 人が判断(明示的な確定アクション)
  受講生がSTEP3完了画面で:
    ・このまま「書籍プロファイルを確定する」を押下 → STEP4へ
    ・STEP1に戻って草案を修正 → 再びSTEP2/3を実行
    ・受講生自身で確定版を一部編集してから保存

確定後、書籍プロファイル確定版が生成され、STEP4以降の入力源となる。
```

**戻りルート**

- STEP2の結果画面: 「STEP1に戻る」ボタン配置(キーワードスコアが低い場合)
- STEP3の結果画面: 「STEP1に戻る」ボタン配置(差別化ポイントが弱い場合)
- 戻り時、STEP2/3の市場データから生成された「コンセプト修正示唆」がSTEP1上部に表示される
- 戻り回数は内部記録(サービス改善指標)

## 9-2. 相談機能(外部AIプロンプト生成パネル)

### 概要

主観・統合のSTEP(STEP0/1/4〜10および書籍プロファイル確定アクション)の各ページに常設される、**外部AI(ChatGPT/Claude.ai)で出力をレビューしてもらうための専用プロンプト生成パネル**。
ai-pub-producerのフロント側で `src/DiscussionPanel.jsx` として実装されている。

このパネルは「ツール内で完結する自動レビュー」ではなく、**ユーザーが既に契約しているChatGPT Plus / Claude Pro等の外部AI**を活用することで、APIコストを発生させずに高品質な戦略レビューを実現する設計。

### 相談機能の対象STEP(v4で整理)

```
相談機能あり:
  STEP0  著者プロファイル
  STEP1  書籍プロファイル草案
  STEP4  エピソードインタビュー(旧STEP3)
  STEP5  タイトル・サブタイトル(旧STEP4)
  STEP6  目次作成(旧STEP5)
  STEP7  章構成作成(旧STEP6)
  STEP8  詳細プロット作成(旧STEP7)
  STEP9  本文作成(旧STEP8)
  STEP10 Amazon説明文作成(旧STEP9)
  書籍プロファイル確定アクション(新規)

相談機能なし:
  STEP2  キーワード絞り込み
  STEP3  競合レビュー評価

理由:
  STEP2/3はAmazon実データに基づく客観分析。外部AIは元データを
  持たないため、評価しても机上の意見しか返せない。AI判定アシスト
  (機械的なスコア判定)で代替する。
```

### 設計の経緯

1. **当初(Phase 1)**: 内蔵チャットでAIと議論する設計
2. **Phase 1.5**: ターン制限・work_profile軽量化・Prompt Cachingでコスト削減
3. **方針転換**: ユーザーフィードバックで内蔵チャットを廃止
   - 理由: 狭いテキストエリア、永遠のラリー、APIコスト発生
4. **現在**: 外部AI用のプロンプトを生成するパネルに変身
   - ChatGPT/Claude.aiに貼り付けて使う「相談スタンス」から「提案出しスタンス」へ
5. **観点の進化(v3→v4→v5→v6→v7)**:
   - v3: 共通6観点での評価
   - v4: 合格判定(致命的0+△1以下)導入+核3観点に絞り込み+ループ警告UI
   - v5: STEP別観点を4〜5個に拡張、「方向性ズレ」を捕捉
   - v6: 全STEPに「売れる本になるか」観点を追加(購買動機・タイトル訴求力・購買転換率など)
   - v7: 全STEPに「マーケ軸(コア・ベネフィット+出版目標)との整合」観点を追加

### ユーザー操作フロー

```
各STEPの出力を生成済み
  ↓
ページ下部の「外部AIで相談する用プロンプトを取得」を開く
```

### 確定アクションの相談機能観点(v4新規)

書籍プロファイル確定アクションは、STEP1の主観コンセプトとSTEP2/3の客観データを統合した結果。STEP4以降の起点となる重要なドキュメントのため、相談機能を追加する。

**6つの観点:**

1. **コンセプトと市場検証の整合性**
   STEP1の主観コンセプトとSTEP2/3の市場データが矛盾していないか。市場検証で見えた読者ニーズと、当初の想定読者像が乖離していないか。

2. **確定版の網羅性**
   STEP4以降(エピソード・タイトル・章構成・本文)で必要な情報が確定版に揃っているか。情報の抜け漏れがないか。

3. **差別化ポイントの具体性**
   抽象論ではなく、本の中身として表現できる具体的な差別化か。「読者の役に立つ」のような曖昧な表現に留まっていないか。

4. **売れる本としての完成度**
   購買動機・差別化・読者の不満解消が確定版に組み込まれているか。市場検証の結果が「本の価値訴求」に翻訳されているか。

5. **マーケ軸との整合**
   コア・ベネフィット+出版目標と市場検証結果が同じ方向を向いているか。リードマグネット型・ロングセラー型などの出版目標と整合しているか。

6. **STEP4以降への接続性**
   タイトル設計・章構成・本文・Amazon説明文を作る時に、この確定版で迷わず進めるか。STEP4以降のLLMが「これを読んで本を作れる」状態になっているか。

### 1回完結原則(v7の中核ルール)

外部AIレビューが「指摘ゼロ=仕事してない」という構造的バイアスを持つため、ループ防止の3層構造を導入:

1. **初回レビュー時の規範**
   - 全観点を一気に網羅的に評価(後で「実は他にも」を発掘禁止)
   - 質問は1回で全部聞く(連想される質問テーマを予測網羅)
   - 観点で△/✗を付けたら必ず対応する確認質問を入れる
   - 質問は番号+選択肢ベースで「Bα20冊以上」のような圧縮回答が可能に

2. **2回目以降の「再評価モード」(自動切替)**
   - 入力に修正版テキストがあれば自動で再評価モードに入る
   - 新たな問題提起を禁止(観点リストに無い新角度の批判は後出し不可)
   - 前回△/✗だった観点のみ再評価し、改善されていれば✓に倒す

3. **「合格に倒すバイアス」を意識的に持つ**
   - 改善が明らかに進んでいれば多少の違和感は✓にして合格判定
   - 著者の判断で次STEPへ進む判断を尊重

### 出力データのマーカー方式

修正版本文は外部AI側で `<<<出力データ>>>` 〜 `<<<出力データここまで>>>` マーカーで囲まれて返ってくる設計。`cleanOutputText()`が保存時に自動でマーカー間を抽出するため、ユーザーが「お礼の挨拶」「修正版は以下の通りです:」などの前置きごとコピーしても、保存時にノイズが除去される。

### App.jsx側のサポート機能

- **書籍プロファイル確定版から自動コンテキスト抽出**: `extractDiscussionContext()`がSTEP3完了後の確定版から「書籍プロファイル確定版・コア・ベネフィット・出版目標・狙い目の切り口」などを抽出し、レビュープロンプトに同梱する
- **STEP1修正提案の自動反映**: 確定アクションの相談機能が出した「STEP1への修正提案」を、想定読者・ポジショニング等はSTEP1入力欄に、検索キーワード戦略はSTEP2の選定キーワードに、それぞれ別系統で反映できるボタン

### STEP2/3に相談機能を実装しない理由(v4で明文化)

新STEP2(キーワード絞り込み)と新STEP3(競合レビュー評価)には相談機能を実装しない。

**理由:**

1. **役割の重複**: STEP2/3自体がSTEP1のダメ出し機能(市場の現実から見たダメ出し・読者の不満から見たダメ出し)。さらに外部AI相談を入れると、ダメ出しの三重構造になり受講生が混乱する

2. **外部AIが価値を出せない領域**: STEP2/3の出力はAmazon実データに基づく分析。外部AI(ChatGPT/Claude.ai)は元データを持たないため、評価しても机上の意見しか返せない

3. **代替手段(AI判定アシスト)が機能する**: STEP2/3にはスコアベースの機械的判定機能(AI判定アシスト)が実装される。これが客観データの判定として機能する

4. **設計の明確化**: 「主観・統合のSTEPには相談、データ分析STEPには相談なし」というルールで、機能の役割が明確になる

### AI判定アシスト(STEP2/3の代替機能)

STEP2/3には相談機能の代わりに、機械的な判定機能を実装する。

**STEP2のAI判定アシスト:**
- 推奨キーワード数が0個 → STEP1に戻る推奨
- 推奨キーワード数が1個以上 → STEP3へ進む推奨
- 戻り推奨時、STEP1への修正示唆フィードバックを自動生成

**STEP3のAI判定アシスト:**
- 差別化ポイントが2個以下 → STEP1に戻る推奨
- 差別化ポイントが3個以上 → 確定アクションへ進む推奨
- 戻り推奨時、STEP1への修正示唆フィードバックを自動生成

これにより、外部AIに頼らずにSTEP1〜3の循環判断ができる。最終的な統合チェックは確定アクションの相談機能で行う設計。

## 10. STEP0：著者プロファイル

### 概要

著者の核(ジャンル横断で安定する軸)を抽出・保持するための機能。生成された著者プロファイルはSTEP1〜STEP15のすべてに自動注入される。

これは「**書籍プロファイル**」(STEP1〜3で本ごとに確立される、書籍固有の設計)と対をなす概念。両者の二層構造によって、シリーズ展開しても著者の核がブレず、かつ各書籍が固有の市場ポジションを持てる設計とする。

### 重要な設計制約

**書籍の主題そのものは抽出しない。ジャンル横断で通用する軸のみを抽出する。**

過去の書籍を入力素材にすると、LLMはどうしても「その書籍に書かれた内容」を専門領域や思想として抽出しようとする。これを防ぐため、プロンプトで以下を明示する：

- 専門領域・強み：書籍の主題ではなく、**著者が他ジャンルの本を書いても通底する軸**
- 思想・価値観：書籍内で語られた主張ではなく、**書き方・選び方に滲む価値観**
- **ターゲット読者像は STEP0 では抽出しない**（書籍ごとに変わるため、STEP1 で本ごとに決める）
- **「読者の成長ストーリー」も STEP0 では抽出しない**（書籍シリーズ単位で本ごとに決める）

### 画面フロー

```
書籍ファイル / Note・X投稿 / プロフィール文 / 既存プロファイル を貼付
　↓
LLM が5項目を抽出して著者プロファイルを生成
　↓
「プロファイルを保存」→ メインメニューへ
```

### 入力

| 入力欄 | 内容 | 任意/必須 |
|--------|------|----------|
| 書籍ファイル × 3枠 | .txt .md .pdf .docx（ブラウザ側で抽出） | 任意 |
| Note・X投稿記事 | テキスト貼り付け | 任意 |
| プロフィール・著者ページ | テキスト貼り付け | 任意 |
| 既存プロファイル | 5000字（更新時のみ・進化型更新用） | 任意 |

※ いずれか1つ以上は必要

### 処理
- ブラウザ側でファイルから本文抽出（pdfjs-dist + mammoth）
- 全テキストを統合してDifyへ送信
- LLM が5項目を抽出して著者プロファイルを生成

### 出力（共通フォーマット）

```
【著者プロファイル】

■ 専門領域・強み
（ジャンル横断で通底する軸）

■ 思想・価値観
（書き方に滲む価値観）

■ 文体・フレーズ
（特徴的な表現・口調）

■ 実績・経歴サマリー
（出版実績・キャリア）

■ 著者の発信スタンス
（書籍ジャンルを超えて一貫した姿勢／立ち位置）
```

> **旧版からの変更点（重要）**：
> - 「ターゲット読者像」項目を削除 → 書籍ごとに変わるため STEP1（書籍プロファイル草案）で決める
> - 「ブランドコンセプト・シリーズ方針」→「著者の発信スタンス」に変更（読者の成長ストーリーは削除）
> - 6項目 → 5項目構成に整理
>
> 理由：旧版では著者プロファイルに「書籍に依存する内容（ターゲット・成長ストーリー）」が混入し、
> STEP1 以降の書籍プロファイル設計の自由度を奪っていた。著者プロファイルは「書籍を超えて普遍的な
> 著者の特性」だけに絞ることで、本ごとに自由にターゲット・コンセプトを設計できる。

## 11. STEPの全体構成

設計書本版では、STEP数は**全16ステップ(STEP0 + STEP1〜STEP15)**となる。

**v3改修の経緯(2026-05改修):**
旧STEP2「市場検証→書籍プロファイル確定」を、新STEP2「キーワード絞り込み」と新STEP3「競合レビュー評価」の2つに分割。市場検証の精度を上げ、Amazon APIで読者の真のニーズを取得できるようにした。書籍プロファイル確定は「明示的な確定アクション」に変更し、受講生が判断するフローに改善。

**STEP3 廃止の経緯(2026-05改修):**
旧STEP3(読者・価値設計)はSTEP2確定版(書籍プロファイル)と内容がほぼ重複していたため廃止。旧STEP3で生成していた章構造ブロックは新STEP6(目次作成)に統合し、章タイトル+節見出しを一気通貫で生成する設計に変更。

### 【書籍プロファイル確立フェーズ】

| STEP | 機能 | 状態 |
|------|------|------|
| STEP1 | 書籍プロファイル草案 | **改訂**(検索キーワード3軸を削除、コンセプト設計に専念) |
| STEP2 | キーワード絞り込み(市場検証) | **新規実装**(Real-Time Amazon Data API活用) |
| STEP3 | 競合レビュー評価(市場検証) | **新規実装**(Real-Time Amazon Data API活用) |
| (確定) | 書籍プロファイル確定アクション | **新規実装**(受講生の明示的ボタン押下) |

**STEP1の詳細:**
- 出力フォーマットから「検索キーワード3軸」を削除
- 残りの項目(仮テーマ・想定読者・コア・ベネフィット・動機・出版目標・著者の角度・ポジショニング仮説・読了後の状態仮説)は維持
- STEP2/3から戻ってきた場合、画面上部に「市場検証からのフィードバック」が表示される

**STEP2の詳細(新規):**
- 入力: STEP1の草案
- 処理:
  1. LLMでキーワード候補10個を生成
  2. 各キーワードでProduct Search API呼び出し(10並列)
  3. 取得データから機械スコアリング(需要・競合の弱さ)
  4. LLMで意図合致スコア判定
  5. 合計スコアで上位2個にAI推奨マーク付与
- 出力: スコア表 + 上位本データ(ASIN含む、STEP3で再利用)
- 受講生の操作: 1〜2個のメインキーワードを選定
- 戻りルート: AI判定で「合計スコア低」の場合、STEP1に戻る推奨

**STEP3の詳細(新規):**
- 入力: STEP2で選定したキーワードと上位本ASIN
- 処理:
  1. 上位3冊のTop Product Reviews APIを呼び出し(cookie不要・PoC検証済み)
  2. rating_distribution(★分布)とレビュー本文を取得
  3. LLMで読者の不満点・差別化ポイント・落とし穴を抽出
- 出力:
  - 読者の共通不満点
  - 既存本がカバーできていない切り口
  - 本企画が差別化できるポイント
  - 注意すべき落とし穴
- 戻りルート: AI判定で「差別化ポイント弱」の場合、STEP1に戻る推奨

**書籍プロファイル確定アクションの詳細(新規):**
- タイミング: STEP3完了後
- 操作: 受講生が「書籍プロファイルを確定する」ボタンを押下
- 処理:
  1. STEP1草案 + STEP2のキーワード戦略 + STEP3の差別化分析をマージ
  2. 書籍プロファイル確定版を自動生成(プレビュー表示)
  3. 受講生が確定版を確認・編集可能
  4. 「保存」ボタンで確定→STEP4へ
- 確定版のフォーマット: マークダウン構造化テキスト(STEP4以降が参照)
- STEP4以降の入力構造は変更不要(既存の書籍プロファイル参照設計を維持)

**STEP1〜3の関係性:**
- STEP1↔STEP2↔STEP3 の単方向フロー(進む順)
- 戻る場合は常にSTEP1へ(複雑な分岐を避ける)
- 書籍プロファイル確定は受講生の判断で実行
- 確定後、STEP3に進むと書籍プロファイルはロック(警告付きで解除可)

**STEP11（X投稿生成 / SNS用短文記事）の詳細**:
- 出版前後の販促用「**短文記事**（240〜280字）」を**1本ずつイテレーション生成**（25本一括生成は LLM の文字数規律が崩壊するため不採用）
- 「ツイート」「X投稿」というラベルを**プロンプト上で意図的に避け**、「SNS用短文記事」とリフレーミング（Twitter prior バイアス回避）
- **毎日投稿型の配分**：N本生成なら「出版(N-1)/2日前 → 出版当日 → 出版後 (N-1)/2 日」の対称配分
  - 15本：出版7日前〜前日（7本）+ 出版当日（1本）+ 出版翌日〜1週間後（7本）= 計15日分
- 文字数オプション：短文140字 / 標準280字 の2択（長文Premium向け3000字は max_tokens 制約と Cloudflare 504 リスクで削除）
- 各投稿に「推奨投稿日（日本語表記）」「タイミング区分」「用途タグ」「文字数」を付与
- 著者プロファイルの固有実績（累計出版冊数・印税・商業出版実績・東工大院・中小企業診断士 等）を **3割以上で引用必須**
- 禁止表現リスト：「お楽しみに」「ぜひ」「新しい○○」「秘密」「秘訣」「いよいよ」「成長しましょう」等のAI量産マーケコピーを明示禁止
- ハッシュタグ：投稿につき0〜1個、創作タグ禁止
- URL は含めない（テキスト本文のみ）
- プレゼント情報入力欄は採用せず（実装当初は検討したが「URL も入れない」方針と整合させてシンプル化）

**STEP12（本の改善提案）の詳細**:
- **位置づけ**：「出版した本を改善することに集中する」STEPとして再定義
  - 次回作・著者プロファイル更新は **STEP13 へ完全分離**
  - 旧設計の「STEP14 出版状況分析」から「次回作引き継ぎ事項」セクションを削除
- 入力: ASIN（必須・B0で始まる10文字）、KDP手動データ（任意・売上巻数/KU既読/印税）、キャンペーン記述（任意・無料キャンペーン/セール/広告/SNS発信）、著者プロファイル・書籍プロファイル確定版（自動転記）
- API: **Real-Time Amazon Data API（RapidAPI）** を使用（Keepa は採用しない）
  - `/product-details` で現状（タイトル・価格・評価・レビュー件数・カテゴリランキング）取得
  - `/top-product-reviews` で最新レビュー取得（★分布・本文）
  - 既存の `RAPIDAPI_KEY` 環境変数を再利用（STEP2/3 と統一）
- 出力（**3 セクション**マークダウンレポート）:
  1. **現状サマリ**（Amazonデータ + KDP手動データ統合）
  2. **レビュー傾向の客観分析**（高評価/低評価の引用 + ポジショニング実態）
  3. **改善提案**（タイトル・サブタイトル / Amazon説明文 / 価格・施策 / 読者期待値整合）
- 改善案は「コピペできる完成形」レベルの具体性を強制（抽象論禁止）
- 著者プロファイル・書籍プロファイルが利用可能なら参照して改善提案を具体化
- Keepa を採用しなかった理由：
  - 既存のRapidAPI契約をそのまま使い回せる
  - 現状スナップショット＋レビューで「次に何を変えるか」の判断材料には十分
  - 過去推移データ（Keepa の強み）は MVP では不要

**STEP13（出版経験の振り返り）の詳細**:
- **位置づけ**：「**著者として進化する**」STEPとして再定義
  - 主役：著者プロファイル更新案を生成し、STEP0 に反映可能にする
  - 次回作テーマは**参考情報として併記するのみ**（書籍プロファイル草案までは作らない）
  - 旧設計の「STEP15 次回作構想」が「新プロジェクト自動開始」前提だったのを変更：**著者の判断を尊重し、強制的な転記はしない**
- 入力: STEP12 改善提案レポート（自動転記・必須）、現在の著者プロファイル（自動転記・必須）、振り返りコメント（任意・著者の自由記述）、書籍プロファイル確定版（任意・参考）
- 出力（**2 セクション**）:
  1. **著者プロファイル更新版**（編集可能な完成形マークダウン）
     - 既存セクション構成（■ 専門領域・強み / ■ 思想・価値観 / ■ 文体・フレーズ / ■ 実績・経歴サマリー / ■ 著者の発信スタンス）を維持
     - 出版経験で得た固有概念・主張・スキルを反映
     - 数字・実績の更新（累計出版冊数・新商業出版・読者評価データ等）
     - LLM 出力に余計な見出し（`## 【著者プロファイル】` 等）が混入した場合、**フロント側で defensive 削除**
  2. **次回作テーマ候補**（参考・3〜5案）
     - 各案：タイトル候補（仮）＋ 1〜2 行の概要のみ
     - 「気になる案があれば STEP1 で改めて入力してください」と明示（自動転記しない）
- UI: 著者プロファイル更新版は textarea で編集可能 → 「✓ STEP0 に反映する」ボタンで `localStorage` を上書き
- 完了後の選択肢:
  - 著者プロファイル更新を STEP0 に反映（推奨）
  - 何もしないでアプリを閉じる（次回作を急がない判断）
  - STEP1 へ手動で進む（新プロジェクトを始めるなら著者が判断して進む）
- これにより設計書セクション7「全体フロー(循環設計)」の循環ループが**著者の意思決定を尊重する形で**具体化される

## 12. シリーズ設計レイヤー

現時点では、シリーズ設計のうち「著者ブランドの一貫性」は著者プロファイル（STEP0）の「著者の発信スタンス」項目で担う。本ごとのテーマ・読者像・成長ストーリーは書籍プロファイル（STEP1〜2）で決める。

## 19. プレゼント特典の運用方針

### 方針

プレゼント特典は **機能としてツールに組み込まず、サブスクサービス
「Life Book Navigator」の会員特典として、運営者（著者本人）が手動で
作成・配布する運用** とする。

### 理由

1. **販促効果の最大化**：プレゼントが豪華であるほど本の販促力が高まる。
   AI生成のテンプレ的なプレゼントより、運営者が選別・制作した「届けたいもの」
   の方が読者体験が深く、結果として本が売れやすくなる。

2. **サブスクの差別化要素**：プレゼントを「サブスク会員特典」として位置付ける
   ことで、Life Book Navigator の契約価値を高められる。本書の読者を
   サブスク誘導する明確な動機付けにもなる。

3. **A+コンテンツとセットで判断**：A+コンテンツも当初Phase 3で計画していたが、
   画像はCanvaで別途・テキストだけ自動生成という中途半端な切り出しになるため
   計画から削除。販促周辺の機能は「サービス側の手仕事」として位置付ける。

### ツール側で対応する箇所

- **STEP10(Amazon説明文)**: 従来どおりサブスク誘導は控えめに1段落のみ(既存設計のまま)
- **STEP13(X投稿)**: プレゼント情報をユーザーが手動入力する欄を設ける。
  入力があれば告知投稿(予告・配布・締切3本)を生成、空欄なら通常投稿のみ。
  プレゼントの企画・制作・配布はツール外で運営者が実施する。

### 影響を受けない既存設計

- リードマグネット書としての本書の位置付け(STEP1動機セクションでの判定ロジック)は維持。
  「本書は導線役の本である」という設計判断は引き続き有効。本書がサブスクへの誘導路として
  機能するという全体構造は変わらない。
- STEP1〜10のプロンプト・出力フォーマットは変更不要(v3でSTEP4以降の入力構造は変えない設計)。
