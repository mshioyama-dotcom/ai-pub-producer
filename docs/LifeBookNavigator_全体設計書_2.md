## 7. 全体フロー（循環設計）

二層プロファイル（著者プロファイル × 書籍プロファイル）による循環構造。

```
┌──────────────────────────────────────┐
│ STEP0  著者プロファイル作成・更新     │ ← 全STEPに自動注入
└────────────┬─────────────────────────┘
             ↓
┌────────────────────────────┐
│ STEP1  書籍プロファイル草案  │
│        ↓                   │
│ STEP2  書籍プロファイル確定  │
│        （確定版を直接編集）  │
└────────────┬───────────────┘
             ↓
┌────────────────────────────────────────┐
│ STEP3〜9  制作（エピソード→本文→説明文）│
│ STEP12   出版後プロモーション（X投稿）  │
└────────────┬───────────────────────────┘
             ↓
┌──────────────────────────────────┐
│ STEP13  出版状況分析（Keepa活用） │
└────────────┬─────────────────────┘
             ↓
┌──────────────────────────────────────────┐
│ STEP15  次回作構想                        │
│   ・候補方向性 → 新書籍プロファイル草案    │
│   ・著者プロファイル更新案                │
└────────┬─────────────────────┬───────────┘
         ↓                     ↓
   ┌──────────────┐     ┌─────────────────┐
   │ 新規プロジェクト │     │ 著者プロファイル │
   │ → STEP1へ      │     │ 更新 → STEP0へ │
   └──────────────┘     └─────────────────┘
   （書籍ごとに循環）        （著者の核は累積進化）
```

### 二層循環の意味

- **書籍プロファイル**は本ごとにリセット → 各本が固有のポジションを持つ
- **著者プロファイル**は累積進化 → 出版を重ねるほど核が強化される
- ユーザは「使うほど自分専用」の体験を、二層構造で実感する

## 9-2. 相談機能（外部AIプロンプト生成パネル）

### 概要

全STEP（STEP0〜STEP9）の各ページに常設される、**外部AI（ChatGPT／Claude.ai）で出力をレビューしてもらうための専用プロンプト生成パネル**。
ai-pub-producer のフロント側で `src/DiscussionPanel.jsx` として実装されている。

このパネルは「ツール内で完結する自動レビュー」ではなく、**ユーザーが既に契約している ChatGPT Plus / Claude Pro 等の外部AI** を活用することで、API コストを発生させずに高品質な戦略レビューを実現する設計。

### 設計の経緯

1. **当初（Phase 1）**：内蔵チャットでAIと議論する設計
2. **Phase 1.5**：ターン制限・work_profile軽量化・Prompt Caching でコスト削減
3. **方針転換**：ユーザーフィードバックで内蔵チャットを廃止
   - 理由：狭いテキストエリア、永遠のラリー、API コスト発生
4. **現在**：外部AI用のプロンプトを生成するパネルに変身
   - ChatGPT / Claude.ai に貼り付けて使う「相談スタンス」から「提案出しスタンス」へ
5. **観点の進化**（v3→v4→v5→v6→v7）：
   - v3: 共通6観点での評価
   - v4: 合格判定（致命的0＋△1以下）導入＋核3観点に絞り込み＋ループ警告UI
   - v5: STEP別観点を4〜5個に拡張、「方向性ズレ」を捕捉
   - v6: 全STEPに「売れる本になるか」観点を追加（購買動機・タイトル訴求力・購買転換率など）
   - v7: 全STEPに「マーケ軸（コア・ベネフィット＋出版目標）との整合」観点を追加

### ユーザー操作フロー

```
各STEPの出力を生成済み
　↓
ページ下部の「📋 外部AIで相談する用プロンプトを取得」を開く
　↓
表示される長文プロンプト（textarea）をコピー
　↓
ChatGPT or Claude.ai に貼り付けて送信
　↓
AIが①率直な判定 ②一番の問題 ③各観点での評価 ④総評 ⑤修正版 を返す
　↓
合格なら「✅ 合格：このまま次STEPへ進んでOK」で終了
不合格なら確認質問→ユーザー回答→修正版完全形を AI が出す
　↓
修正版本文は <<<出力データ>>> 〜 <<<出力データここまで>>> マーカーで囲まれる
　↓
ユーザーがマーカーごとコピー → ツールの「出力データ」欄に貼り付け
　↓
保存時に cleanOutputText() が自動でマーカー間を抽出（前置きノイズ自動除去）
```

### 1回完結原則（v7の中核ルール）

外部AI レビューが「指摘ゼロ＝仕事してない」という構造的バイアスを持つため、ループ防止の3層構造を導入：

1. **初回レビュー時の規範**
   - 全観点を一気に網羅的に評価（後で「実は他にも」を発掘禁止）
   - 質問は1回で全部聞く（連想される質問テーマを予測網羅）
   - 観点で △/✗ を付けたら必ず対応する確認質問を入れる
   - 質問は番号＋選択肢ベースで「Bα20冊以上」のような圧縮回答が可能に

2. **2回目以降の「再評価モード」（自動切替）**
   - 入力に修正版テキストがあれば自動で再評価モードに入る
   - 新たな問題提起を禁止（観点リストに無い新角度の批判は後出し不可）
   - 前回 △/✗ だった観点のみ再評価し、改善されていれば ✓ に倒す

3. **「合格に倒すバイアス」を意識的に持つ**
   - 改善が明らかに進んでいれば多少の違和感は ✓ にして合格判定
   - 著者の判断で次STEPへ進む判断を尊重

### 出力データのマーカー方式

修正版本文は外部AI 側で `<<<出力データ>>>` 〜 `<<<出力データここまで>>>` マーカーで囲まれて返ってくる設計。`cleanOutputText()` が保存時に自動でマーカー間を抽出するため、ユーザーが「お礼の挨拶」「修正版は以下の通りです：」などの前置きごとコピーしても、保存時にノイズが除去される。

### App.jsx 側のサポート機能

- **書籍プロファイル確定版から自動コンテキスト抽出**：`extractDiscussionContext()` がSTEP2 出力から「書籍プロファイル確定版・コア・ベネフィット・出版目標・狙い目の切り口」などを抽出し、レビュープロンプトに同梱する
- **STEP1修正提案の自動反映**：STEP2 が出した「STEP1への修正提案」を、想定読者・ポジショニング等は STEP1 入力欄に、検索キーワード3軸は STEP2 入力欄に、それぞれ別系統で反映できるボタン

## 10. STEP0：著者プロファイル

### 概要

著者の核（ジャンル横断で安定する軸）を抽出・保持するための機能。生成された著者プロファイルはSTEP1〜STEP14のすべてに自動注入される。

これは「**書籍プロファイル**」（STEP1〜2で本ごとに確立される、書籍固有の設計）と対をなす概念。両者の二層構造によって、シリーズ展開しても著者の核がブレず、かつ各書籍が固有の市場ポジションを持てる設計とする。

### 重要な設計制約

**書籍の主題そのものは抽出しない。ジャンル横断で通用する軸のみを抽出する。**

過去の書籍を入力素材にすると、LLMはどうしても「その書籍に書かれた内容」を専門領域や思想として抽出しようとする。これを防ぐため、プロンプトで以下を明示する：

- 専門領域・強み：書籍の主題ではなく、**著者が他ジャンルの本を書いても通底する軸**
- 思想・価値観：書籍内で語られた主張ではなく、**書き方・選び方に滲む価値観**
- **ターゲット読者像は STEP0 では抽出しない**（書籍ごとに変わるため、STEP1 で本ごとに決める）
- **「読者の成長ストーリー」も STEP0 では抽出しない**（書籍シリーズ単位で本ごとに決める）

### 画面フロー

```
書籍ファイル / Note・X投稿 / プロフィール文 / 既存プロファイル を貼付
　↓
LLM が5項目を抽出して著者プロファイルを生成
　↓
「プロファイルを保存」→ メインメニューへ
```

### 入力

| 入力欄 | 内容 | 任意/必須 |
|--------|------|----------|
| 書籍ファイル × 3枠 | .txt .md .pdf .docx（ブラウザ側で抽出） | 任意 |
| Note・X投稿記事 | テキスト貼り付け | 任意 |
| プロフィール・著者ページ | テキスト貼り付け | 任意 |
| 既存プロファイル | 5000字（更新時のみ・進化型更新用） | 任意 |

※ いずれか1つ以上は必要

### 処理
- ブラウザ側でファイルから本文抽出（pdfjs-dist + mammoth）
- 全テキストを統合してDifyへ送信
- LLM が5項目を抽出して著者プロファイルを生成

■ 思想・価値観

■ 文体・フレーズ
（特徴的な表現・口調）

> **旧版からの変更点（重要）**：
> - 「ターゲット読者像」項目を削除 → 書籍ごとに変わるため STEP1（書籍プロファイル草案）で決める
> - 「ブランドコンセプト・シリーズ方針」→「著者の発信スタンス」に変更（読者の成長ストーリーは削除）

> STEP1 以降の書籍プロファイル設計の自由度を奪っていた。著者プロファイルは「書籍を超えて普遍的な

**STEP1 の出力構造（マーケ軸補強済み・現行）：**
- 仮テーマ／想定読者(仮説)／**コア・ベネフィット**（読者目線の約束1文）／動機／**出版目標**（リードマグネット／ロングセラー化／権威付け 等のチェック＋自由記述）／著者の角度／ポジショニング仮説／読了後の状態仮説／検索キーワード3軸（厳格に2語）

**STEP2 の役割（Keepa 廃止後の現行設計）：**
- 旧仕様（〜2026年5月）の Keepa API による数値分析（ランキング・レビュー数・売上推移）は廃止
- 新仕様の役割は **「整合性チェック ＋ 市場検証 ＋ ブラッシュアップ」の3段階**：
  1. **整合性診断**（守り）：草案 × 市場の3観点（読者軸×コア・ベネフィット ／ 検索KW×ポジショニング ／ 市場ジャンル×本書ジャンル）を ✓/△/✗ で診断
  2. **市場検証**（攻めの抽出）：Amazon 検索結果 HTML から上位本のタイトル・著者・評価・価格を抽出し、クリック語の傾向・空白地帯・競合分布を構造化
  3. **ブラッシュアップ**（攻めの反映）：市場知見を草案に積極反映して表現を磨く。**草案のコア（仮テーマ・コア・ベネフィット・出版目標・想定読者のメインジャンル）は維持**し、「市場の引力でジャンルが歪む」現象を構造的に防ぐ
- 整合性 ✗ が出ても **確定版は必ず全項目を出力**（冒頭に警告コメント付き・暫定確定版）。STEP1 修正提案も並行して出る
- フロント側 UI は2系統フロー：
  - **フロー A**（検索キーワード3軸のみの修正）→ STEP2 入力欄に直接反映ボタンで完結
  - **フロー B**（想定読者・ポジショニング等の修正）→ STEP1 に戻ってフィールド反映 → 再生成 → STEP2 再実行
- STEP3以降が参照するのは「STEP2 で保存された確定版」のみ

## 12. シリーズ設計レイヤー

現時点では、シリーズ設計のうち「著者ブランドの一貫性」は著者プロファイル（STEP0）の「著者の発信スタンス」項目で担う。本ごとのテーマ・読者像・成長ストーリーは書籍プロファイル（STEP1〜2）で決める。

二層プロファイル構造の導入により、シリーズ全体の安定軸は **著者プロファイルが担う**（出版を重ねるごとに累積進化）、各書籍の固有設計は **書籍プロファイルが担う**（STEP1〜2で本ごとに確立）、という形で**暗黙的にシリーズ設計が機能する**。

## 19. プレゼント特典の運用方針

### 方針

プレゼント特典は **機能としてツールに組み込まず、サブスクサービス
「Life Book Navigator」の会員特典として、運営者（著者本人）が手動で
作成・配布する運用** とする。

### 理由

1. **販促効果の最大化**：プレゼントが豪華であるほど本の販促力が高まる。
   AI生成のテンプレ的なプレゼントより、運営者が選別・制作した「届けたいもの」
   の方が読者体験が深く、結果として本が売れやすくなる。

2. **サブスクの差別化要素**：プレゼントを「サブスク会員特典」として位置付ける
   ことで、Life Book Navigator の契約価値を高められる。本書の読者を
   サブスク誘導する明確な動機付けにもなる。

3. **A+コンテンツとセットで判断**：A+コンテンツも当初Phase 3で計画していたが、
   画像はCanvaで別途・テキストだけ自動生成という中途半端な切り出しになるため
   計画から削除。販促周辺の機能は「サービス側の手仕事」として位置付ける。

### ツール側で対応する箇所

- **STEP9（Amazon説明文）**：従来どおりサブスク誘導は控えめに1段落のみ（既存設計のまま）
- **STEP12（X投稿）**：プレゼント情報をユーザーが手動入力する欄を設ける。
  入力があれば告知投稿（予告・配布・締切3本）を生成、空欄なら通常投稿のみ。
  プレゼントの企画・制作・配布はツール外で運営者が実施する。

### 影響を受けない既存設計

- リードマグネット書としての本書の位置付け（STEP1 動機セクションでの判定ロジック）は維持。
  「本書は導線役の本である」という設計判断は引き続き有効。本書がサブスクへの誘導路として
  機能するという全体構造は変わらない。
- STEP1〜9 のプロンプト・出力フォーマットは変更不要。
